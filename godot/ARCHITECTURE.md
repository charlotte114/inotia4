# 能力现状与运行方式

> **inotia4** 用 Godot 4.5 + C# 实现，运行在原生 Android 与桌面。规则、内容与素材从原版《艾诺迪亚4》（1.2.9）逆向得到，逆向资料在 `inotia4/`。
>
> 历史核对结论已并入 `inotia4/docs/` 的逆向记录与 `godot/tests` 的回归用例。

## 现在能做什么

启动即进入黑暗骑士团营地（`shadow-camp`）：三层地图（地面 / 景物 / 顶盖）、83 个景物、12 个地图人物、按 Y 排序的前后遮挡、镜头跟随、移动输入（键盘、虚拟摇杆／符文十字键／四向移动三档、点地面自动寻路）、地形阻挡、**走到出口会切换地图**（带 24 像素回程锁与 0.28 秒黑场淡入）。位置、朝向、游戏时间与地图访问次数记在 `Session` 里，切图不丢。实测 164–165 fps。

**触屏与手机**：左下虚拟摇杆（另有符文十字键、四向移动两档可选），右下普攻大钮与六格快捷位，左缘常驻两枚圆钮（存档 / 设置）。键位能在设置里拖着改，工具条右端可整体缩放 70%–140%（位置与档位存 `control-layout.json`）。设置页里「高帧率」（默认开：跟屏幕刷新率走，安卓上关 vsync 并请求高刷模式；关掉就锁 60 并开 vsync）与「震动」（命中 18ms、自身挨打 28ms）都是手机向的开关，标题页与游戏内同名同义。**安卓返回键**先关最上面那层菜单页，一层都没开才开系统页当暂停菜单——不再直接结束进程（`quit_on_go_back=false`），所以中途退回桌面不会丢现场。

**战斗（`--arena`）**：一只 1 级蝙蝠主动追击，空格或 `J` 出招。命中走完整的闪避 → 盾挡 → 武器格挡 → 暴击判定链，伤害按防御/抗性换算，屏幕正中的目标窗（名字 + 血槽）、飘伤害数字、受击闪红、倒下淡出、主角倒下原地重置都已接好。

**地图上的怪**：248 张图共 2553 个刷怪点按主角等级选档（例如训练场二层 35 个点，1 级只放 5 级档的 11 只），可破坏物槽会按 5%／2% 换成罐子怪或箱子怪；怪物按 `battle.json` 的 `behavior` 决定动不动手（树丛／罐子不还手，被动怪挨打才还手），击败后 60 秒复活、一次性生成点永久消失，血魔随存档往返。

**怪物的行动**（怪物逐个决策）：每 60 毫秒一次决策、每个物理步走一段路。主动怪按察觉范围把主角记进仇恨账本再扑上来，被动怪要挨过一次打才会还手；追近走八像素网格 A*（预算每渲染帧 512 个扩展，几十只怪一起算不卡），一路追不上就 180 毫秒重算、算不出路就 600 毫秒后再试。追丢、被撤下或仇恨清零之后自己走回出生点；带 `wander` 配置的怪在原地待机一段时间后按原版的掷骰规则闲逛（先掷要不要转身、再掷走几步）。

**打怪有经验，站着会回血**：击杀普通怪按等级差与队伍人数折算给经验（等级差修正 ±8／+5 档、队伍人数每多一人折减 20%），经验够了当场升级——面板重算、生命魔力回满，HUD 与人物页同步。景物怪、自检代打不计经验。每 31 个逻辑帧（1.86 秒）一次资源恢复脉冲：主角按「成员档」回 `trunc((960+36×等级)÷10)` 点生命与 8 点魔力，怪物的生命基数是 0（原版就是 0）只回魔；同一个脉冲顺带让仇恨账本衰减一次。

**角色数值与初始装备**：1 级黑暗骑士按 `character-stats.json` + `items.json` 算出真实面板——徒手攻 10，配上职业初始的长剑与盾后是 **攻 18 / 魔攻 19 / 血 1672 / 防 24 / 减伤 230‰ / 命中 956‰ / 暴击 70‰ / 盾挡 120‰**。装备词条按原版算法掷骰（同一件装备永远同一组词条），强化等级按卷轴规则加值。

**剧情演出与触发**：普通启动就是新的一局——先自动演开场（接下第一个任务），之后靠 593 条事件触发器推进：走到区域（`region`，178 条）、任务到状态（`quest`，192 条）、靠近物件（`near`，92 条）、选过选项（`choice`，101 条）、事件链（`event`，9 条）、进图（`map-entry`）。触发器每物理帧检查（窄区域轮询会漏），且先于出口判定（两者的区域常常重叠）。剧本遭遇战走原版那条路：`waitEncounter` 把遭遇登记成 `active` 交给世界名册布怪，剧情转 waiting、操作权交回玩家，清场或倒下后回填胜负，再从 `outcomes.won`／`lost` 续播。

**剧情世界**：剧情改过的世界（谁被摆到哪、谁被撤下、哪些敌人按图禁用或换位、出口开关、旗标与选择）现在记在会话的 `StoryWorld` 里，随存档往返；每次进图由它投影出人物名单——营地 12 人、森林西侧 6 人，摆位、朝向与「开过的箱子不再出现」都从这份状态算出来。

**舞台与世界分离**（舞台与世界分离）：`stage` 演出项画的是**舞台自己的地图**，正式世界被隐藏、会话与出口完全冻结；舞台里的玩家是独立演出演员，走位、对白只动他；剧本收尾才把舞台玩家的最终位置用 `travel` 语义提交回正式世界。`world` 命令（place/remove-character/actor-visibility/travel）在节点演出**之前**执行（原版 prepare → begin 的次序），演员先落位，appear/walk 才有对象和坐标。

`--storyaudit 700` 是覆盖率的守门指标：把 693 段剧本各跑一遍（只推进状态机不演出），统计每段停在哪。当前 **693 段全部正常结束**（branch / choice / waitEncounter 都已接通；审计中遭遇战自动判胜）。

**任务与战斗**：击杀计数与物品计数都会推进任务目标（265 个 `defeat` 目标 + 151 个 `item` 目标，集齐后任务变「可交付」），HUD 显示当前任务指引（`◆ 任务标题：目标 n/m`），接任务/任务完成有弹窗（`quest-popup`，475 处）。剧本遭遇战按原版语义挂起与续播：怪在场上打，清场后剧情自己接着走。敌人出手走原版口径：射程按八像素量化碰撞盒距离，出招按 `basicAttacks` 的周期与命中帧结算（93 份普攻规则、553 只敌人 548 份绑定），动作素材按逻辑帧取帧。**技能双侧接线已完成**：主角/伙伴走 `PlayerCastSkill`（技能页与快捷栏起手），敌人按 battle.json 的绑定选技施放（释放条件、每场一次、冷却与站位门槛全按原版），命中后二十一种技能反应与十六步命中反应链随接线生效；54 门主动技能经 `--skillplaycheck` 逐个实放冒烟全过（六职业各 9/9 受理、零失败）。

**宝箱**：地图上 87 处宝箱摆放每次进图掷一次原生 1..99（普通宝箱 29% 出现，优质宝箱降级后约 11.6%）。走到箱子身边 24 像素、正面朝着它按 `E` 开箱：按地图的宝箱等级（`chestLevel`，没有就用 `lootLevel`，再没有按 1 级）掷一次掉落，保底加成按宝箱档位记账，开出来的东西落在箱子脚下；出场规则里那 100 的槽位基数按原版公式折算（等级相当时约 1%），引出的是「古代的魔箱怪」。箱子 600 毫秒淡出后消失，本次访问不再出现；剧情摆放的一次性宝箱开过之后跨访问也不再出现。

**职业选择**：标题页点「开始游戏」先进职业选择——六个职业各有图标、说明、五行初始值和一段待机预览，选中格加亮，底部「开始游戏」才真正装配会话。职业决定角色卡（1 级忍者是血 1592／攻 16／暴击 130‰，黑暗骑士是血 1672／攻 18／暴击 70‰）、初始装备与主角的战斗动作；剧情姿态仍取自主角定义。读档直接进世界，职业从存档里读（标题页存档槽会显示「LV.1 · 忍者」这样的职业名）。

**背包与装备账本**：散装物品、五个分类袋各自的格位、全部页的独立格位、穿在身上的实例、伙伴装备、
十二格快捷栏、配方本都在 `domain/Character/Bag.cs` 里，逐条按背包规则实现。穿脱是原子的
（双手武器挤掉副手、副手要先有主手、换下的装备落进新装备腾出的那一格），拖动落格、整理收拢空位、
堆叠与拆栈、强化与宝石写在实例上、用途没实现的物品拒绝而不销毁都已接上。面板现在从背包读装备，
不再有第二份装备表。**页面上的拖放**也接好了：格子上按住 350 毫秒起拖，落到别的格子换位／交换、
落到装备槽穿上、落到另一件物品上用掉；丢弃走原版那块 450×350 的操作弹层（−／＋／全部 + 确定／取消）。

**融合器与合成台**：地图上的融合器（`service: fusion-machine`）按 `E` 开合成页。融合器挂的是可重复
任务，所以「有任务先对话」会让合成台被长期挡住——现在说完话（接任务／交付／念进度）会紧接着把合成页
打开，交互完总能进到合成界面。版面照原版
`UIMix_CreateMainControl` 的控件树（见 `SO_REVERSE.md` §17.11）。左栏是**三副面孔**叠在同一块区域、
靠切换显隐：先进来是**五行满宽菜单**（药水合成／宝石强化／宝石孔生成／混沌合成／传说装备，
442 宽、行高 = 字高 + 41、行底是图集 19 那枚深色胶囊），点一行换成**这一类的配方列表**
（滚动区 (49,90)、321 宽、行高 56）或直接进**加工区**（合成格 (223,62)＋材料组 (70,239) 四格＋
「组合」钮 (149,360)）；左上角一枚「菜单」钮回上一层。混沌合成列的是混沌／深渊混沌两档。
加工区里合成格两侧还有两枚金色三角，在「能当目标的装备」之间循环切换（原版
`UIMix_ButtonUpExe/DownExe`，见 `SO_REVERSE.md` §17.14）。
右栏是背包格（4×4、步长 83）与分类列、底部三枚币，框与原版同为 431 高、与左栏底边对齐。
点「组合」先出报价，再弹原版那条横贯全屏的原生提示确认；材料不足、金币不足、已到上限等情况
走同一块提示显示理由（文案取 `menu-panels.json` 的 `itemMessages`）。提交会扣材料，
并按混沌规则重掷目标的数值与等级。固定产出类（药水、宝石、传说装备）还能**批量合成**：
材料组与「组合」之间那行 `− 批量 ×N ＋` 调次数，材料按次数累计、整批一次事务提交
（这是本项目加的功能，原版一次只做一份，见 `SO_REVERSE.md` §17.13）。

**技能页**（按 `K` 打开）：左栏是队伍列与三列技能格——主动技能两列、被动一列，未学的格子盖一层
半透明遮罩、学过的右下角带等级角标，选中的格子套金色大圆环；右栏是「技能点: n」标题带与说明区：
`技能名 (LV n)` → 介绍 → 每行详情（魔耗、冷却、各项效果，数值按蓝色高亮）→ 浅蓝点线 →
「条件：投入 n 技能点 / 需要技能点数」→ 下一级预览（只列会变的项，冷却不列，旧值→新值，魔耗蓝、效果红）。
底部两枚原版按钮：「学习」立即扣点，「快捷键」进登记屏（已登记则变成「取消快捷键」）。
说明区与技能格都能滚动；页签里的「AI 设置」「设置」读队伍名册——正常游戏里名册开局就建好，
两页都可用（只有构造技能页时没传名册才灰掉，与原版无队伍时同口径）。

**快捷键登记屏**：菜单整块让位，露出压暗的画面；顶部一行「请选择要设置的快捷键。」，
右下角一排出六个圆槽与换组钮（位置按操作区默认键位算），屏幕中间偏右单独画着待登记的对象，
左上角一枚圆形关闭钮。点一格就落格，技能槽再点一次是取消，落完留在这一屏继续登记。
技能页的「快捷键」与背包物品详情里的「快捷键」都进这一屏（原版两处调同一个 `openShortcutScreen`），
登的是同一行十二格；物品侧点「取消快捷键」把该物品从两组里一次清掉。

**菜单页签**：人物页、背包页与技能页顶部都画着原版那排六个页签（人物／背包／技能／队伍／任务／系统）——
命中区 102×116、x=35 步进 149、图标 78×78、文案 20 号居中，当前页不透明、其余 0.65。
点六页页签都能互切（人物／背包／技能／队伍／任务／系统）。

**人物页**：左栏立绘卡（等级／职业／名字）与三条槽（生命／魔法／经验），中列五行属性，
右列十二行战斗数值；右上角「能力点」带与加号进入加点视图——五行各配左右步进钮（可长按连点），
暂存的增量以橙色 +N 显示，点右上那枚勾钮就**直接写回**（原版的「确定按当前分配增加能力？」
确认框按用户要求于 2026-11-12 去掉），「能力初始化」一键清空已分配的点。

**世界内状态栏与切换操控**：右上角那套按状态栏规范——大面板常驻**当前操控者**
（头像跟着人换：主角用皮肤里的 `player-portrait`，剧情伙伴用立绘的 partyIcon，佣兵用职业图，
即取当前操控者的头像），下面竖排其余成员，点一块就切操控。切换会停掉旧被控者的
走位与动作、全体 AI 下一逻辑帧各自重判，主角交给托管 AI 跟随／追近——**托管 AI 的位移只挪主角**，
不会把刚接手的伙伴拖着走（`MoveActor` 显式区分「挪谁」，`--switchcheck` 钉住这两条）。

**任务页**：左栏任务组列表（主线组在前、组内按任务表倒序，每行配 MAIN／可交付角标），
右栏同组各段任务的详情正文——完成段整段灰掉、目标数值红字、说话人与对话目标蓝字，
逐字断行、行尾不留起始标点；默认选中第一组并展开详情，滚动列表只收起详情不换选中项。

**NPC 交互**：走到人物身边 24 像素内（曼哈顿距离，与原版同口径），HUD 出现「E 交谈」提示与任务标记。按 `E` 交互——有任务的 NPC 按原版任务槽优先级（可交付独占 → 主线 → 支线 → 进行中）走接取/交付/进度；交付会收走任务物品、发经验金钱装备、弹带奖励清单的完成窗；没任务的 NPC 说闲话（商人念他的招牌词）。

已验证的切图路径：`shadow-camp` → 出口 (392, 312) → `shadow-forest-west`，落点 (40, 168)。

调试参数（写在 `--` 之后）：

| 参数 | 作用 |
|---|---|
| `--shot` | 跑 150 帧后截图到 `godot/.shots/world.png` 并退出 |
| `--fpsprobe` | 每 60 帧打印一次实时帧率 |
| `--map <id>` | 直接进入指定地图，落点取地图中心最近的可站位置 |
| `--face <dir>` | 进图时按指定方向站定（south / west / north / east） |
| `--exitcheck` | 自动走向最近的出口，验证切图后退出（无头模式下也能跑） |
| `--interactcheck` | 站到营地杂货商人旁边走一遍交互链路：选人 → 计划 → 闲话（无头也能跑） |
| `--npccheck` | NPC 功能分派：在 `--map delos-cave-9172c82a` 上站到插在地上的剑旁边按一次交互，核对「提示 → 按职业发武器 → 剑消失 → 不重复领取」；加 `--npcfunc <编号>` 可只验一条（0 旅馆休息、39 复活同伴） |
| `--arena` | 在主角旁边放一只 1 级蝙蝠，验证战斗流程（空格或 `J` 攻击） |
| `--panel` / `--gear` | 打印初始装备清单与「徒手 / 装备后」两套面板，核对数值公式 |
| `--texaudit <n>` | 连续切 n 张景物密集地图再原路返回，贴图数回不到基线就以退出码 1 失败 |
| `--story [脚本id]` | 播一段剧本；不填则从 `campaign.json` 的 start 开始。无头模式下自动翻页并在演完后退出 |
| `--storyaudit <n>` | 前 n 段剧本各跑一遍，统计停在哪（正常结束 / choice / waitEncounter） |
| `--placementcheck` | 配合 `--story`：演完回营地验证剧情摆放的 NPC（如卓拉德）真的上场 |

## 三个关键决定

**1. `domain` 是独立类库，不是文件夹。** 原版的纪律是「领域层不依赖渲染引擎」，这里把它变成编译期约束：`Inotia4.Domain.csproj` 根本不引用 Godot，想 import 也 import 不到。所以通行判定、移动求解这类规则可以脱离引擎跑测试，测试项目也不需要拉起 Godot 运行时。

**2. 运行时读 `public/`，不让 Godot 预导入素材。** 素材有 11,556 张 PNG。走 Godot 的导入管线意味着整个素材库进包、编辑器卡在导入上、`.godot` 缓存几个 GB。这套做法原版里本来就是「进这张图才加载这张图要的素材」，这里沿用：`ContentRoot` 定位到仓库的 `public/`，`TextureCache` 按需解码。导出到 Android 时 `res://` 不再是文件路径，所以先由 `godot/tools/pack_game_data.py` 把 `public/` 打成 `game_data.zip` 随包分发，读到哪个文件才从包里解哪个（见下），之后的读取路径不变。

**2.1 内容包是按需解包的，而且自带 zip 读取器。** 首启只写一个版本标记，文件在第一次被读到时才解出来（实测首启只落 99 个文件、解包 0.24 秒）。这里**不能用引擎的 `ZipReader`**：它按名字查条目的成本随条目数线性涨，这个包 12,200 条，读一个 205 字节的小图要 120 毫秒，整套解完就是二十分钟以上。所以有 `PackedContent`——自己解析中央目录成字典，之后每个文件两次 seek，实测每次 0.01 毫秒；stored 与 deflate 都支持，失败时退回整包解包（`ExtractAll`）。换内容包后目录会被清空重建（签名是包的字节数）。

**3. 不引入 NUnit。** 原版用零外部依赖的断言器，换机器不用先还原一堆包。这里对应地写了一个几十行的断言器：`dotnet run` 就能跑，失败数决定退出码。
